# CReM dock-first Pareto (new)

Same iterative workflow as `iterative_dock_pareto`; CReM replaces GenMol and proposes context-aware analogs from a fragment database. Start from caffeine with `--starting-smiles "Cn1c(=O)c2c(ncn2C)n(C)c1=O"`. Install CReM in the workflow's Python environment (`pip install crem`) and provide a CReM database using `--crem-db /path/to/fragments.db` or `CREM_DB`. Controls include `--crem-mode` (`mutate`, `grow`, or both; default), `--crem-radius`, `--crem-max-size`, `--crem-growth-max-atoms`, and `--generator-max-output`. CReM offers explicit fragment/context and property filtering, but requires a prepared, chemically representative fragment DB. Each timestamped run is stored under `outputs/crem_dock_pareto/` with numbered round folders, per-round figures, and end-of-run `pareto_evolution.png` and `run_metrics.png` summaries. Rebuild the latter figures from a saved run without docking using `python scripts/iterative_dock_pareto/plot_run_figures.py outputs/crem_dock_pareto/<run-folder>`. See the [generation](https://crem.readthedocs.io/en/stable/operations/mutate-grow-link/) and [database build](https://crem.readthedocs.io/en/stable/fragment-databases/build-v2/) docs.
