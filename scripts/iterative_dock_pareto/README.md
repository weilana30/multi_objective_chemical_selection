# Iterative dock-first Pareto workflow

This is the current iterative dock-first workflow. It generates candidates, docks each unique molecule, keeps every candidate whose docking score is strictly better than the caffeine reference, and calculates solubility and lipophilicity scores only for those survivors. The Pareto front is recalculated over all scored molecules from earlier rounds in the same run, so a molecule can leave the front when a later candidate dominates it. The run stops at the requested number of transitions (default: five) or when it runs out of novel candidates.

The caffeine score is calculated at the start of each run with the same receptor and Vina settings used for candidates. “Better” means a higher `docking_score` (equivalent to a more negative docking affinity). There is no top-20 cap. If a round has no candidates above the caffeine cutoff, the run stops.

By default, round 0 is de novo. Use `--starting-smiles` to seed it. The default target is 1,000 dock candidates across the full run (`--total-candidate-budget`), split into geometrically smaller batches according to `--candidate-decay`. Before generation, the workflow uses each round's budget to choose its Pareto parent count, mask-size range, and samples per mask. If valid unique output falls short, it makes up to five differently seeded batches (`--max-generation-batches`), stopping early after two batches add no new molecules. `--initial-mask-count`, `--min-mask-tokens`, `--max-mask-tokens`, and `--max-pareto-parents` constrain those choices. Cached molecules are reused. The Pareto objective directions are higher aggregate lipophilicity and higher aggregate solubility.

The persistent SQLite cache defaults to `outputs/iterative_dock_pareto/molecule_cache.sqlite3`. It stores canonical SMILES, docking/property scores and failures, whether a molecule has ever been Pareto, and the run/rounds where it appeared on a front. Compatible earlier runs in this output folder are imported once. Global outputs are refreshed after each round: `global_scored_archive.csv`, `global_pareto.csv`, and `molecule_cache.csv`. Each run also receives a `global_pareto.csv` and an incrementally updated `workflow_summary.json`.

To continue an interrupted run, pass its existing output directory with `--output-dir <run-folder> --resume`. Saved candidate CSVs are reused and completed predictions are read from the cache.

Requires the GenMol environment/model, the local AutoDock Vina service, and the registered property services. Each run is organized under `outputs/iterative_dock_pareto/<run>/`; reference, service status, summary, and global front stay at the run root, while numbered `round_XX/` folders contain that round's candidates, docking, survivors, property scores, Pareto front, generation metadata, and summary figure. A `global_pareto.png` is refreshed after each round. On completion, `pareto_evolution.png` shows the round-by-round fronts and their sizes, while `run_metrics.png` summarizes generated, docked, passing, and final Pareto molecule counts. Regenerate these two figures from existing data with `python scripts/iterative_dock_pareto/plot_run_figures.py outputs/iterative_dock_pareto/<run>`.
